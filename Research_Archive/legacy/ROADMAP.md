# Дорожная карта: Unity от А до Я

**Дата составления:** 2026-10-08. **Трекер:** [issue #1](https://github.com/spels1992/Unity/issues/1). **Статус:** план составлен; главы исследуются по порядку, параллельно поддерживается каталог источников.

## Процесс разработки — один непрерывный цикл

```text
Идея → Целевая аудитория → Анализ аналогов → Концепт и ограничения
  ↓
GDD + технические решения + оценка риска
  ↓
Быстрые прототипы → тесты гипотез → GO / PIVOT / STOP
  ↓
Vertical Slice → план производства → основная разработка
  ↓
Контент + механики + UX + звук + локализация
  ↓
Тестирование → производительность → полировка
  ↓
Сборки → возрастные рейтинги/права → сертификация/магазины
  ↓
Релиз → аналитика → обновления → поддержка → ретроспектива
```

В любой момент проект можно остановить, упростить или переориентировать. **Прототип** проверяет интересность идеи с минимальным контентом; **вертикальный срез** демонстрирует одно законченное, близкое к финальному по качеству игровое впечатление. Это разные артефакты.

Проверять их в каждом релевантном разделе: Git/Git LFS; *source of truth*; CI/CD и supply chain; лицензии каждого ассета и пакета; настройка доступности; локализация; миграции сохранений; privacy; оптимизация; стоимость; работа без бюджета; проверка на настоящем целевом устройстве.

## Метод поиска для каждой главы
1. Выписать цели, ключевые вопросы, применимые версии Unity и термины.
2. Найти официальные документацию, API, tutorials/Unity Learn и release notes.
3. Сравнить примеры проектов Unity и реальные исходники; дополнить форумами/issue/инженерными статьями с маркировкой качества.
4. Зафиксировать варианты: **бесплатно/платно**, лицензия, поддержка, сложность, компромиссы, платформы.
5. Сформулировать воспроизводимые шаги, тесты, минимальный практический пример, ошибки и способы исправления.
6. Записать Markdown по теме + источник в `SOURCES.md` + коммит; ссылка на коммит или файл в журнале; только после этого двигаться дальше.
7. Провести дополнительный круг поиска, если остаются пробелы или данные сомнительны.

## Условия, чтобы отметить тему [x]
- Нет критических пустот в вопросах темы; есть конкретные действия/примеры и условия применения.
- Факты проверены по актуальным первоисточникам с датой и по возможности версией.
- Указаны цена/лицензия/совместимость, если речь о стороннем решении.
- Есть явный список ограничений и непроверенного; не выдается мнение за спецификацию.
- Файл сохранён в GitHub и проверен чтением из репозитория.
- Новый поиск перестал выявлять существенно новые решения (**насыщение**, а не невозможная «проверка всего интернета»).

## План базового рабочего проекта (рекомендация, не окончательное решение)
Начать с небольшой однопользовательской игры без онлайна. Отдельно проверить 2D и 3D направления, затем выбрать одно после прототипов. Сначала добиться стабильной сборки для Windows и одной механики; многопользовательский режим, магазин и сложную графику добавлять только если они действительно требуются.

## Политика непрерывного сохранения
**Каждый законченный шаг в чате должен соответствовать сохранённому Markdown-коммиту**. Перед остановкой: проверить отредактированные файлы через GitHub, добавить источники и нерешённые вопросы. Если публикация не удалась — явно сообщить, что шаг НЕ сохранён, и не объявлять его завершённым.
