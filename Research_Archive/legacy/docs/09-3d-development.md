# 09. Unity 3D: миры, модели, физика, камера

**Первая редакция:** 2026-10-08 · **Статус:** схема принятия решений, требуется выполнение на Unity и сравнение импорта Blender.

## Поток работы над 3D игрой
```text
Концепт/референсы → блокинг уровня кубами → камера/контроллер
  ↓
Основная механика → тесты масштаба и управления
  ↓
Модели и материалы → UV/текстуры → импорт
  ↓
Коллайдеры + Rigidbody/CharacterController
  ↓
Анимация/rigging/IK → свет/тени → VFX/звук
  ↓
Профилирование → LOD/occlusion/batching → сборка
```

## Модель → Unity
- Источник ассетов — отдельный каталог/Blender, управляемый Git LFS если файлы большие и квота позволяет.
- Проверять **масштаб единиц**, оси и направления, положение pivot, нормали, topology, UV, материалы, риг и клипы анимации.
- Использовать формат экспорта (например FBX) с документированной настройкой; `.blend` напрямую в pipeline возможен в ряде сценариев, но повышает зависимость от внешней установленной программы и версий импортера. Выбор согласовывать по платформе и окружению.
- Не переносить PBR/шейдеры 1:1 без проверки — Blender и Unity используют разные материал/рендер системы.
- Проверять итог в Player, не только Scene view.

## Физика Unity 3D
Для объектно-ориентированного 3D Unity документирует **PhysX**, а для 2D — **Box2D**. В 3D Collider задаёт невидимую форму столкновения, Rigidbody добавляет физическое тело; Trigger детектирует пересечения вместо блокировки движения. Проектировать слои и матрицу столкновений заранее.

| Объект | Первичный компонент | Вопрос к проекту |
|---|---|---|
| Пол | Collider, обычно без Rigidbody | Статичная ли поверхность? |
| Физический ящик | Rigidbody + BoxCollider | Масса и тип движения? |
| Сигнальная зона | IsTrigger Collider | Есть ли Rigidbody в паре? |
| Игрок | CharacterController либо Rigidbody-вариант | Нужны ли физические толчки/скольжение? |
| Дальний фон | MeshRenderer, при необходимости LOD | Надо ли рассчитывать его collisions? |

Источник: [Physics integrations](https://docs.unity.com/en-us/engine/6000.3/manual/physics-section/physics-integrations), [Introduction to collision](https://docs.unity.com/en-us/engine/6000.3/manual/physics-section/physics-overview/collision-section/colliders-overview), [Built-in 3D physics](https://docs.unity.com/en-us/engine/6000.0/manual/physics-section/physics-overview).

## Выбор рендера
| Pipeline | Когда рассмотреть | Ограничения |
|---|---|---|
| Built-in | Поддержка наследованных проектов/специфических шейдеров | Не тот же pipeline, что URP/HDRP |
| URP | Базовый выбор для широкого спектра 2D/3D и платформ | Специфика Render Features/шейдеров, нужна проверка целевых устройств |
| HDRP | Цели высокого визуального качества на поддерживаемых мощных платформах | Не переносить на mobile/WebGL без учёта поддержки (официальная матрица указывает ограничения) |

Матрица: [Render pipeline feature comparison (Unity 6.3)](https://docs.unity.com/en-us/engine/6000.3/manual/render-pipelines/choose-a-render-pipeline/feature-comparison).

## Мини-проект для обучения
1. Создать пустую 3D сцену, плоскость, куб, свет и камеру.
2. Привязать куб к Rigidbody с BoxCollider; запустить и проверить падение на плоскость.
3. Добавить статичное препятствие и Trigger-зону; регистрировать событие отдельно.
4. Протестировать контроллер персонажа без готовых сторонних ассетов; сравнить Rigidbody и CharacterController.
5. Добавить простую модель Blender через экспорт FBX, проверить размер и orientation.
6. Сравнить простой материал, освещение и shadow cost на целевой машине.
7. Сделать тестовый build для Windows и проверить, что взаимодействие работает вне Editor.

## Критерии хорошего 3D производства
- Масштаб персонажа, двери и окружения согласованы.
- Механика работает в greybox сцене **до** дорогого изготовления моделей.
- Камера не мешает обзору и не требует постоянной ручной коррекции.
- У каждой модели зафиксированы лицензия и источник.
- Collision meshes проще визуальных meshes там, где это возможно.
- Свет/тени/LOD измеряются через Profiler/Frame Debugger на целевой платформе.
- FBX импорт воспроизводим после `git clone` и чистого импорта.
