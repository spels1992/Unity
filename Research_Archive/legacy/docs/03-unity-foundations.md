# 03. Unity: редактор, версии, лицензии, первый проект

**Источники проверены:** 2026-10-08 · **Стадия:** исследование базового рабочего процесса; тест на ПК ещё не выполнен.

## Что такое Unity и как связаны части
- **Unity Hub** — отдельное приложение для установки разных версий Editor, управления проектами, учётной записью и лицензией.
- **Unity Editor** — приложение, в котором редактируются сцены, код, графика, физика и готовятся сборки.
- **Unity Engine/Player** — среда выполнения игры после сборки; Editor и Player — не одно и то же.
- **Unity Package Manager (UPM)** — управление пакетами через редактор и `Packages/manifest.json`.
- **Asset Store** — каталог ресурсов и инструментов со своими условиями лицензирования.

## Какие версии рассматривать в октябре 2026
- **Unity 6.3 (6000.3)** официально обозначена как LTS в документации по обновлению.
- **Unity 6.6 (6000.6)** выпущена 31 августа 2026, официально обозначена как **Supported release**, а не LTS. Официальный анонс от 1 сентября 2026 утверждает поддержку до следующего релиза 6.7.
- **Рекомендация для нового стабильного проекта:** начать сравнение на 6.3 LTS, а 6.6 использовать только после оценки нужных функций, регрессий, плагинов и пакетов. Это **рекомендация**, а не доказательство того, что 6.3 всегда надёжнее для любого проекта.
- Точная установленная версия на компьютере **пока не проверена**; не повышать проект через Editor «просто потому, что вышло обновление».

Первичные источники: [6.3 LTS upgrade guide](https://docs.unity.com/en-us/engine/6000.6/manual/upgrade-guides/upgrade-guide-unity63), [Unity 6.6 release notes](https://unity.com/releases/editor/whats-new/6000.6.0f1), [официальный анонс 6.6](https://discussions.unity.com/t/unity-6-6-is-now-available/1735357), [migration 6.5→6.6](https://docs.unity.com/en-us/engine/6000.6/manual/upgrade-guides/upgrade-guide-unity66).

## Установка и создание первого проекта: чек-лист

1. Установить Unity Hub из официального источника, войти в Unity ID, проверить активную лицензию.
2. Через Hub → **Installs** выбрать редактор. Отдельно добавить нужные **Build Support** модули только для целевых платформ (например, Windows, Web или Android).
3. Через Hub → **Projects → New project** выбрать Editor version, шаблон (Core/Sample/Learning), указать понятное название и папку на локальном диске.
4. Для учебной 2D игры выбрать подходящий 2D шаблон, для 3D — простой шаблон с URP, если платформа/графика это оправдывают. Не брать HDRP для простейшей мобильной игры без теста совместимости.
5. Создать проект и дождаться импорта ассетов. Не закрывать редактор принудительно во время первого импорта.
6. Изучить панели **Hierarchy** (объекты сцены), **Scene** (редактор), **Game** (камера игрока), **Inspector** (свойства), **Project** (файлы), **Console** (ошибки и логи).
7. Создать сцену `Main`, один GameObject, компонент и простой скрипт MonoBehaviour; убедиться, что Play Mode входит и выходит без ошибок в Console.
8. Зафиксировать Editor version и список пакетов, подключить Git, сделать initial commit (отдельный репозиторий кода — не путать с данной энциклопедией).
9. Сделать **пустую тестовую сборку** под первую платформу, убедиться, что она запускается вне Editor; сохранить скриншоты и логи.
10. Закрепить версию Editor на время прототипа; любые обновления проводить отдельной веткой с backup и checklist регрессии.

См. [Unity Hub: Create a project](https://docs.unity.com/en-us/hub/project-create), [Install Unity](https://docs.unity.com/en-us/engine/6000.3/manual/get-started/install-and-upgrade/getting-started-installing-unity), [Unity Editor windows](https://docs.unity.com/en-us/engine/6000.3/manual/unity-editor/editor-settings-reference/comp-manager-group).

## Как устроена сцена (краткий словарь)
- **Scene** — файл с игровыми объектами и ссылками на ресурсы.
- **GameObject** — контейнер компонентов; его Transform задаёт положение, поворот и масштаб.
- **Component** — поведение/свойство: Renderer, Collider, Rigidbody, MonoBehaviour.
- **Prefab** — переиспользуемый шаблон объекта; его варианты нужно изучить отдельно.
- **ScriptableObject** — объект данных, пригоден для хранения настроек/конфигурации, но не универсальная система savegames.
- **Build** — собранное приложение на конкретную платформу, не то же самое, что кнопка Play.

## Критичные проверки и ограничения
- Совместимость пакетов зависит от Editor; проверять Package Manager для выбранной ветки.
- После обновления Unity 6.6 **Cinemachine 3** является core package и происходит migration со старого Cinemachine 2. Если проект содержит Cinemachine 2 — отдельный тест и резервная ветка **обязательны**.
- Unity **не рекомендует** хранить рабочий каталог проекта в автоматически синхронизируемой облачной папке: это может повреждать файлы при конфликте. Использовать Git или иной version control; облако можно применять как backup/export.
- Установленная версия, корректность Windows build modules, настройки лицензии и тестовая сборка на машине не проверялись в этой документальной фазе.
