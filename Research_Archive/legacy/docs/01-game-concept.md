# 01. Идея и проверка жизнеспособности игры

**Первая редакция:** 2026-10-08. **Стадия:** начальная практическая глава; маркетинговые цифры и игроки пока не исследованы.

## Порядок действий

### Шаг 1. Одно предложение
«Игрок [роль] делает [основное действие] ради [цели], сталкивается с [ограничение/опасность], а отличие игры — [уникальная особенность]».

**Пример для учебной игры:** «Лучник стреляет по пугалам с ограниченным числом стрел, рассчитывает дугу полёта и взаимодействует с препятствиями; каждый уровень проверяет одну новую траекторию». Это концепция для проверки, не утверждённое ТЗ.

### Шаг 2. Паспорт продукта
| Поле | Решение/вопрос |
|---|---|
| Целевой игрок | Возраст, опыт, мотивация, тип сессии, доступность |
| Платформа | Windows, Web, Android/iOS, консоль? Приоритет — одна |
| Ввод | Мышь/клавиатура, геймпад, touch? Требования к UI |
| Жанр/камера | 2D платформер, пазл, 3D приключение и т.п. |
| Механика | Действие, реакция системы, препятствие, обратная связь |
| Core loop | Что повторяется каждые 10–60 сек и почему интересно |
| Долгий цикл | Новые уровни, способности, задачи, прогресс |
| Уникальность | Чем отличаемся от 3–5 ближайших аналогов |
| Модель выпуска | Бесплатная, платная, учебная? На каком магазине |
| Ограничения | Срок, команда, бюджет, права на ассеты, сложность |
| Метрика успеха | Прохождение первого уровня, время сессии, субъективный fun |

### Шаг 3. Изучить существующие игры
Сформировать таблицу 5–10 похожих игр: что хорошо работает, что игроки критикуют, как реализованы обучение/ввод/сложность/визуал. Отдельно — оценки и субъективные гипотезы. Не копировать чужие оригинальные графику, код или брендинг.

### Шаг 4. Проверить рискованные предположения
- Понимает ли тестировщик управление без инструкции?
- Интересно ли 3–5 минут играть с одной механикой?
- Реально ли сделать это одному человеку?
- Проходит ли механика на целевом устройстве?
- Требуется ли multiplayer или сложный 3D, если тот же эффект доступен в 2D?

### Шаг 5. Прототип
Сначала серые примитивы, 1 действие, 1 условие победы/поражения, рестарт; никаких меню-магазинов и большого арт-пайплайна. Затем 3–5 независимых тестировщиков (размер — практическая стартовая рекомендация, не научно установленный минимум), фиксировать наблюдаемое поведение, не только отзывы.

## Core loop на примере лучника
```text
Игрок целится → выбирает силу/направление → стреляет
    ↓
Смотрит, как сработали дуга и препятствия
    ↓
Получает обратную связь/очки/ошибку
    ↓
Меняет план → повторяет → поражает пугало → новый уровень
```

**Измерения:** доля попаданий, число попыток до успеха, уровень оттока, жалобы на управление, FPS.

## GO / PIVOT / STOP
- **GO:** ключевое действие интересно в прототипе, понятно, технически выполнимо; scope небольшой.
- **PIVOT:** игрокам нравится ядро, но механика, платформа или жанр требуют смены.
- **STOP:** механика не увлекает, бюджет/технический риск непропорционален ожидаемой отдаче.

## Выходные артефакты
- `CONCEPT_ONE_PAGER.md` — 1 страница.
- `COMPETITOR_MATRIX.md` — реальные аналоги со ссылками и датами.
- `ASSUMPTIONS.md` — список критичных гипотез и план проверки.
- Прототип с видео/сборкой, известными ограничениями и результатами игрового теста.
- Предварительный выбор одной основной платформы.

## Типовые ошибки
1. «Хочу MMORPG уровня AAA» вместо одной проверяемой механики.
2. Многопользовательская архитектура раньше теста основного действия.
3. Выбор рендеринга по красивому скриншоту, а не по платформе и производительности.
4. Огромный GDD без играбельной проверки.
5. Оценка лишь по собственному мнению автора.

## Источники и что они подтверждают
- [Unity Learn — Prototyping](https://learn.unity.com/course/design-and-publish-your-original-game-unity-usc-games-unlocked/unit/prototyping): проверять, интересна ли игра, прототипами и планировать ассеты.
- [Unity Learn — Milestones](https://learn.unity.com/course/design-and-publish-your-original-game-unity-usc-games-unlocked/unit/milestones): разбивать проект на milestones, использовать vertical slice.
- [Unity Learn — Set up your project](https://learn.unity.com/tutorial/66f53a14edbc2a0e75d4fe90): организацию задач и прохождение от идеи к вертикальному срезу.
- [Unity — Game Designer Playbook](https://unity.com/resources/game-designer-playbook): обзор прикладных инструментов прототипирования.

## Не исследовано полностью
Спрос по жанрам по конкретным платформам, возрастные ограничения, финансы и прогноз продаж. Они требуют отдельного текущего рыночного исследования для выбранной игры.
