# Unity — обязательные правила локального хранения
## Обязательный скилл для 3D-моделей — 3D Craft

При создании или доработке любой собственной 3D-модели, деталей, одежды и аксессуаров перед работой прочитать [docs/3D_CRAFT.md](docs/3D_CRAFT.md) и проверить, что скилл [3D Craft](https://chatgpt.com/plugins/plugins_6acdc74c86888191b2101b657a2e8f8d) (`3d-craft`) **реально активен**. Если недоступен — `BLOCKED`, не запускать другой 3D-конвейер вместо него без разрешения. ComfyUI не разрешён внутри 3D Craft. Сохранять существующие правила хранения, Unity-импорта и проверок.


## Актуальная 3D-модель Кошки-Картошки

**При любых новых задачах по персонажу брать только `D:\Blender\Models\Koshka-Kartoshka\Koshka-Kartoshka_MAIN_StableFast3D_1024.blend`** — выбранный результат Stable Fast 3D 1024, а не устаревшие ручные v01–v56. Исходный GLB и история удаления прежних версий: [KOSHKA_KARTOSHKA_MAIN_MODEL.md](KOSHKA_KARTOSHKA_MAIN_MODEL.md). Новые правки сохранять отдельными версиями; базовый файл не перезаписывать без необходимости.

## Запуск локальных редакторов

Не добавлять Blender или Unity в автозапуск Windows и не настраивать их автоматическое восстановление. Запускать редакторы только для явно поставленных задач. Сторожами могут управляться только явно разрешённые фоновые службы и их туннели.

## Единые локальные папки AI-заготовок (обязательно)

- **ComfyUI:** `D:\Blender\Comfy\3D заготовки` — промежуточные изображения, текстуры и заготовки ComfyUI.
- **Stable Fast 3D:** `D:\Blender\Stable 3D\3D заготовки` — GLB, черновые 3D-модели, рендеры, QA и промежуточные результаты SF3D.
- Каждый персонаж/объект получает свою подписанную подпапку. Финальные утверждённые модели и .blend хранить отдельно в `D:\Blender\Models\<имя модели>\`.
- Сами программы установлены в `D:\Program Files\`; не смешивать каталоги результатов с библиотеками, весами и кэшами.
- Подробности: **[LOCAL_ASSET_PATHS.md](LOCAL_ASSET_PATHS.md)**. Использовать это правило перед каждым AI→Blender→Unity заданием. Токены и большие черновики на GitHub не загружать.


## Канонический корень
Единственный корень Unity-материалов: `D:\Unity\`. Не создавать Unity-проекты, тестовые копии, сборки или рабочие каталоги непосредственно в корне диска D: и не использовать `D:\FarmDev\`.

## Верхний уровень
- `D:\Unity\Projects\` — только именованные игровые/прикладные проекты.
- `D:\Unity\Tools\` — общие инструменты, editor tooling, утилиты и скрипты, применимые к нескольким проектам.
- `D:\Unity\Templates\` — общие шаблоны/заготовки.
- `D:\Unity\SharedAssets\` — общие легально используемые ассеты, которые не принадлежат одному проекту.
- `D:\Unity\Archives\` — сознательно архивированные материалы; не использовать как рабочее место.

## Проекты
Каждый проект обязан иметь собственную подписанную папку: `D:\Unity\Projects\<ProjectName>\`.
Текущий проект Farm: `D:\Unity\Projects\Farm\`.
Внутри папки конкретного проекта разрешена любая разумная структура. Для Farm канонический Unity/Git workspace: `D:\Unity\Projects\Farm\Source\`, а QA, builds, reports, experiments и project-specific tools должны оставаться внутри `D:\Unity\Projects\Farm\`.

## Запреты
- Не создавать безымянные Run001/Run002 и аналогичные каталоги на верхнем уровне.
- Не создавать новый полный клон проекта ради каждого теста.
- Не складывать project-specific файлы в `D:\Unity\Tools\` или `SharedAssets\`.
- Не переносить legacy-каталоги автоматически: сначала определить Git remote/branch/HEAD/status и уникальные файлы.
- Перед любой записью проверять абсолютный путь и использовать существующую подходящую папку.

## Производство 3D-моделей через 3D Craft (2026-10-13)

Все новые и перерабатываемые собственные 3D-модели обязаны проходить [3D Craft](docs/3D_CRAFT.md). Референсы создаются напрямую или берутся у пользователя; GLB создаётся локальным Stable Fast 3D, сборка и 42 проверки — Blender MCP, игровой импорт/QA — Unity MCP. ComfyUI, Rodin и полноценная ручная лепка вместо SF3D не входят в этот маршрут. Нельзя затрагивать готовые модели без резервных копий, а готовность объявлять без фактического QA.
