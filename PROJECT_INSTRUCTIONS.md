## Универсальное правило запуска и ремонта программ — 16.10.2026

**При разрешённой порученной работе агент сам запускает все необходимые закрытые установленные программы** (Unity, Blender, Hunyuan3D-2GP, SkinTokens и другие), сверяясь с [единым справочником абсолютных путей](https://github.com/spels1992/Farm/blob/main/docs/TOOL_STARTUP_AND_MCP_RECOVERY_RU.md). Если MCP/CLI не отвечает: диагностирует конкретный сбой, выполняет адресное исправление, повторно проверяет реальную функцию и продолжает исходную задачу. **После первой неудачной диагностики останавливаться запрещено.** Если осмысленные попытки не помогли, сохранить лог и checkpoint, самостоятельно взять другую разрешённую задачу, а не объявлять всю разработку заблокированной.

Это не разрешение на защищённые OWNER_ONLY 3D/rig/animation, повторное включение намеренно удалённого Farm Watcher/туннеля или автозапуск GUI монитором. Не запускать второй Unity на одном проекте и не уничтожать несохранённую работу.

Не добавлять Blender или Unity в автозапуск Windows и не настраивать их автоматическое восстановление. Запускать редакторы только для явно поставленных задач. Сторожами могут управляться только явно разрешённые фоновые службы и их туннели.

- **Hunyuan3D-2GP:** `D:\AI-MCP\hunyuan-local\jobs` — GLB, черновые 3D-модели, рендеры, QA и промежуточные результаты Hunyuan3D-2mv.

## Канонический корень
Единственный корень Unity-материалов: `D:\Unity\`. Не создавать Unity-проекты, тестовые копии, сборки или рабочие каталоги непосредственно в корне диска D: и не использовать `D:\FarmDev\`.

## Верхний уровень
- `D:\Unity\Projects\` — только именованные игровые/прикладные проекты.
- `D:\Unity\Tools\` — общие инструменты, editor tooling, утилиты и скрипты, применимые к нескольким проектам.
- `D:\Unity\Templates\` — общие шаблоны/заготовки.
- `D:\Unity\SharedAssets\` — общие легально используемые ассеты, которые не принадлежат одному проекту.
- `D:\Unity\Archives\` — сознательно архивированные материалы; не использовать как рабочее место.

## Проекты
Каждый проект обязан иметь собственную подписанную папку: `D:\Unity\Projects\<ProjectName>\`.
Текущий проект Farm: `D:\Unity\Projects\Farm\`.
Внутри папки конкретного проекта разрешена любая разумная структура. Для Farm канонический Unity/Git workspace: `D:\Unity\Projects\Farm\Source\`, а QA, builds, reports, experiments и project-specific tools должны оставаться внутри `D:\Unity\Projects\Farm\`.

## Запреты
- Не создавать безымянные Run001/Run002 и аналогичные каталоги на верхнем уровне.
- Не создавать новый полный клон проекта ради каждого теста.
- Не складывать project-specific файлы в `D:\Unity\Tools\` или `SharedAssets\`.
- Не переносить legacy-каталоги автоматически: сначала определить Git remote/branch/HEAD/status и уникальные файлы.
- Перед любой записью проверять абсолютный путь и использовать существующую подходящую папку.

## Производство 3D-моделей через 3D Craft (2026-10-13)


## Новый 3D Craft — обязательный четырёхракурсный процесс

Создание 3D: единый согласованный sheet с 4 ортографическими ракурсами (front, back, left, right) → crop в 4 отдельных PNG → локальный Codex Desktop MCP **hunyuan3dLocal** (Hunyuan3D-2GP / 2mv Turbo) → GLB в D:\AI-MCP\hunyuan-local\jobs\<job_id>\result.glb → Blender QA/раскраска → Unity QA. При одиночном фото сначала создать один **единый** лист, а не независимо генерировать четыре картинки. Локальная установка D:\Program Files\Hunyuan3D-2GP; окружение .venv, веса models-local и models-cache; MCP D:\AI-MCP\hunyuan-local\hunyuan_mcp.py. В ChatGPT Windows UI основной инструмент WinApp MCP; Desktop Commander только диагностика и ремонт WinApp. Модель пока выводится без текстур, цвет делается отдельным проверенным этапом Blender. Старые реальные файлы не удалять.
