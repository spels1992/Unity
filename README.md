## Принцип работы
1. **Исследование → запись в Markdown → коммит → проверка ссылки → переход к следующему блоку.** Не хранить результаты лишь в переписке.
2. Указывать **дату и версию Unity**, прямой адрес источника, лицензии/стоимость и статус проверки, особенно для меняющихся вещей.
3. Разделять **официальные факты**, **инженерные рекомендации** и **гипотезы/непроверенные данные**.
4. По возможности предпочитать бесплатные инструменты и открытые лицензии, но проверять условия и ограничения каждого пакета.
5. Не копировать чужие книги, курсы и плагины целиком: ссылаться на источники и писать собственные инструкции; код использовать с соблюдением лицензий.
6. Заканчивать исследование **по насыщению**: каждая значимая тема разобрана и подтверждена, а новые источники не приносят существенных решений.

## Как устроены будущие материалы
Для каждой темы: цель → область применения → настройка → пошаговое применение → примеры → варианты и сравнение → типовые ошибки → ограничения/лицензия → тесты → ссылки → дата проверки → пробелы.

## Не перепутать репозитории
Здесь — энциклопедия **Unity**. Реальные игровые проекты и код допускается держать отдельно. **GameLibrary** — общий каталог, а не место для автоматической перезаписи при исследовании.

**Важно:** наличие ссылки на библиотеку не означает, что её совместимость с нашей версией Unity подтверждена. Нельзя называть экспериментальные сведения проверенными.
