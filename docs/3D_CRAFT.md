# 3D Craft — обязательная инструкция для создания и доработки 3D-моделей

**Область применения:** создание, реконструкция, переработка или исправление любой собственной 3D-модели: персонажа, животного, монстра, транспорта, строения, предмета, одежды, брони, оружия, аксессуара, отдельной части и её крепления. Поиск готовых ассетов, 2D-спрайты, обычная работа над кодом игры и редактирование сторонних материалов сами по себе не запускают этот конвейер.

## Проверка при старте задачи — обязательно до любых изменений модели

1. Прочитать корневой `AGENTS.md`, `PROJECT_INSTRUCTIONS.md` и эту инструкцию.
2. Найти и **активировать доступный скилл `3d-craft` (3D Craft — 3Д Крафт)** в текущем ChatGPT/Codex-сеансе. [Приватный плагин 3D Craft](https://chatgpt.com/plugins/plugins_6acdc74c86888191b2101b657a2e8f8d). Если интерфейс поддерживает `@3d-craft`, вызвать его. Упоминание названия в промпте само по себе **не доказывает**, что скилл реально загружен.
3. Прочитать актуальный `SKILL.md` установленного 3D Craft и выполнять его требования. Этот файл — **проектный указатель**, а не замена реального скилла. Если скилл/нужные MCP недоступны — сообщить `BLOCKED: 3D Craft недоступен` и запросить подключение/доступ; **не** объявлять, что он использован, и **не** запускать альтернативный процесс создания новой 3D-модели без отдельного решения владельца.
4. Сверить текущую локальную рабочую копию, статус Git, версии модели, референсы, конфликты других агентов и пути из `LOCAL_ASSET_PATHS.md`. Не трогать исходник без резервной копии.

## Обязательный конвейер

**Изображение-референс (готовое либо созданное напрямую) → локальный Stable Fast 3D → GLB-кандидаты деталей → примерка и сборка в Blender → полный QA с 42 ракурсов → экспорт / проверка в Unity по необходимости.**

- На Windows: `D:\Program Files\StableFast3D\Run-SF3D.cmd`; вход `D:\Program Files\StableFast3D\inputs`; результаты `D:\Blender\Stable 3D\3D заготовки`. Удостовериться в существовании файлов и реальном запуске до заявления о PASS. Облачный `/workspace` — **не** локальный диск D:; перед запуском SF3D подтвердить доставку PNG в Windows.
- **ComfyUI, Rodin и другой 3D-генератор не использовать внутри 3D Craft**; ComfyUI в других, не связанных с 3D Craft задачах не запрещён и не удаляется.
- Blender MCP — работа со сценой; Windows MCP — запуск SF3D, файлы, PowerShell/процессы; WinApp MCP — резерв, если Windows MCP не работает; Unity MCP — импорт/игровой QA; Desktop Commander — только восстановление Windows MCP/WinApp MCP. Существующие разрешения сохранять.
- Беречь удачную базовую геометрию: при проблеме с конкретной частью/аксессуаром сгенерировать **отдельный референс → отдельный GLB → проверить кандидата со всех сторон → временно примерить → заменить только проблемное**. Не переделывать качественную модель из шаров, кубов и примитивов. Blender — прежде всего осмотр, трансформы, стыки, материалы, UV, риг/анимация и сборка.
- Резервная копия перед правкой; только **один писатель** в основной `.blend`. При работе другого агента — своя отдельная копия. Несколько тяжёлых SF3D GPU-прогонов на RTX 4060 8GB одновременно не запускать.
- После каждой **принятой** правки проверять всю модель **42 ракурсами** (36 орбит + 6 ортографических) и крупными планами. Фиксировать «Критическая ошибка», «Серьёзный дефект», «Мелкий недочёт», «Идея улучшения». Пока остаются исправимые критические или серьёзные дефекты — продолжать цикл исправлений и полного осмотра. Если реально нет доступного средства — сохранить и сообщить `BLOCKED`, не писать `READY`.
- Для готовой игровой модели дополнительно проверить масштаб, текстуры, UV, LOD, rig/animation при наличии, Unity import / EditMode / PlayMode согласно задаче. Отсутствующий тест не считается PASS.
- Писать **краткие живые отчёты по значимым этапам** (что сделано, результат, следующий шаг), без повторения сырых `python`/`PowerShell` команд. При длинной работе привлекать независимых субагентов для референсов/анализа/QA, если доступны, с **той же моделью и уровнем рассуждения**, когда это технически поддерживается; не выдавать неподконтрольное совпадение за факт.
- Оставлять существующие каталоги моделей, проекта и approved art gates; не перезаписывать утверждённые исходники. Для Farm сохранять запрет мультяшных production-ассетов и процедуру утверждения животного/монстра.

**При конфликте старой документации** (`ComfyUI → SF3D` либо «при неудаче лепить заново в Blender») для **создания и переработки 3D-моделей** действует этот регламент и актуальный установленный 3D Craft. Это не отменяет правила лицензирования, запрета расходов, хранения, тестов и безопасности.
