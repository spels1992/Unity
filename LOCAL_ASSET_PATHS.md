# Локальные каталоги AI→Blender — единый стандарт

Актуально: 2026-10-12. Для компьютера разработки на Windows (диск **D:**).

## Куда сохранять результаты

| Генератор | Канонический каталог результатов |
|---|---|
| Hunyuan3D-2GP | `D:\AI-MCP\hunyuan-local\jobs` |

**Обязательное правило для всех агентов проекта:** исходные ИИ-заготовки, GLB/OBJ, PNG, текстуры и промежуточные превью складывать в каталог соответствующего генератора. Для каждого объекта/персонажа делать собственную подпапку, например `Koshka-Kartoshka`, `Farm`. Не смешивать заготовки разных генераторов.

**Готовая модель Blender** (мастер-файл .blend и одобренные экспортные ассеты) хранится отдельно в `D:\Blender\Models\<название проекта>`. Не перемещать и не перезаписывать утверждённые модели. После доработки импортировать в Unity только проверенные версии.

## Настройка программ

- Hunyuan3D-2GP установлен отдельно: `D:\Program Files\Hunyuan3D-2GP`. На компьютере `D:\Program Files\Hunyuan3D-2GP\outputs` — NTFS junction на `D:\AI-MCP\hunyuan-local\jobs`: старые скрипты продолжают писать в новый каталог. В новых командах явно указывать `--output-dir "D:\AI-MCP\hunyuan-local\jobs\<имя объекта>"`.
- Уже полученные файлы Кошки-Картошки из Hunyuan3D-2GP скопированы с проверкой SHA-256. Изолированный Hunyuan3D-2mv-прототип не является утверждённым каноном; сравнивать с модельным листом и доводить в Blender.
- Если папки отсутствуют, создать их; не менять пути молча и не использовать папку проекта Unity для необработанных моделей.

## GitHub и права

В GitHub храним **эти инструкции, исходники генераторов, описания пайплайна, манифесты и разрешённые небольшие результаты**, но не автоматически все промежуточные файлы с диска, гигабайтные модели, кэши, токены Hugging Face или локальные конфиги с секретами. Для другого компьютера пути необходимо переназначить явно.

Это соглашение одинаково для трёх репозиториев: `spels1992/Farm`, `spels1992/Unity`, `spels1992/Blender`.
